
Welcome & Overview
You have already written small Python scripts. You have seen lines like balance = 10000 and name = "Amaka". On the surface, it looks like you are putting a value into a box. But that mental model is not quite right, and if you hold on to it, you will eventually get confused when Python behaves in ways that do not match the box idea.

Python does not put values into boxes. Python attaches names to objects that live in the computer’s memory. A variable is a label, not a container.

This distinction matters. It explains why a variable can point to a number today and a string tomorrow. It explains why two variables can refer to the same object. It explains why some values seem to change while others do not. And it gives you a clearer picture of how Python actually stores and manages data.

By the end of this lesson, you should be able to:

Explain variables as names bound to objects in memory.
Describe assignment and rebinding without using the “box” metaphor.
Identify Python’s basic primitive types: int, float, str, bool, and None.
Explain basic immutability of scalar values.
Trace how a variable can change type because types live on objects, not names.
Use type() and id() to inspect values, types, and identity.

Do not rush. This lesson is foundational. A clear mental model of memory will make every future topic easier.
